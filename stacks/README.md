# Stack packs

The workflow (skills, review agents, hooks) knows nothing about any language.
Everything stack-specific lives in a **stack pack**: two files that `/adopt`
copies into a repo.

| File | Becomes | Holds |
| ---- | ------- | ----- |
| `agent-workflow.json` | `.claude/agent-workflow.json` | Data for the hooks: protected files, formatters, paired-file reminders. Validated by [the schema](../schema/agent-workflow.schema.json). |
| `AGENTS.snippet.md` | Sections of `AGENTS.md` | Tech stack, key commands, conventions and absolute rules for agents to read. |

Hooks read data, agents read prose. A rule that a hook can check goes in the
JSON; a rule that needs judgment goes in the snippet.

## Available packs

- [`flutter/`](flutter/) — extracted from Meally, a Flutter app shipping on iOS, Android and the web.

## Adding a pack

Create `stacks/<stack>/` with both files. A pack for a Go service could start
like this:

```json
{
  "$schema": "https://raw.githubusercontent.com/MaTeS72/agent-workflow-kit/main/schema/agent-workflow.schema.json",
  "stack": "go",
  "protected": [
    { "glob": "**/*.pb.go", "reason": "Generated by protoc. Edit the .proto file and run `make proto`." },
    { "glob": "db/migrations/**", "reason": "Applied migrations are immutable. Add a new migration instead.", "allowCreate": true }
  ],
  "formatOnEdit": [{ "glob": "**/*.go", "command": "gofmt -w {file}" }],
  "pairedFiles": [{ "glob": "api/**/*.proto", "reminder": "Regenerate clients with `make proto` and bump the API changelog." }]
}
```

The hook tests in [`hooks/tests/`](../hooks/tests/) already run a Go-shaped
config like this one, so a new pack needs no code changes, only data.
